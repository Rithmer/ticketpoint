# Пользовательские сценарии TicketPoint

В Student Hub преподавателя VIEWER — сотрудник с правом чтения, TEACHER изменяет студентов, ADMIN управляет системой. В TicketPoint роли адаптированы под продажи: USER — покупатель с личными билетами, MANAGER — оператор, ADMIN — управление системой. JavaFX сохраняет прямое JDBC-подключение, как требует КР №2. Те же ограничения действуют в REST API и веб-интерфейсе.

## Права

| Действие | Пользователь | Менеджер | Администратор |
| --- | --- | --- | --- |
| Афиша | Просмотр | Просмотр | Создание, просмотр, изменение, удаление |
| Клиенты | Только свой профиль | Просмотр всех, выбор для заявки | Создание, просмотр, изменение, удаление |
| Создать заявку | Только на себя | На выбранного клиента | На выбранного клиента |
| Список, карточка, поиск, фильтры, сортировки, статистика, экспорт | Только свои | Все | Все |
| Исправить новое бронирование до начала события | Мероприятие | Клиент и мероприятие | Клиент и мероприятие |
| Подтвердить, вернуть подтверждённую заявку на исправление, отметить оплату | Нет | Да | Да |
| Отменить | Своя новая или подтверждённая заявка до начала события | Любой неотменённый билет | Любой неотменённый билет |
| Удалить с подтверждением | Только свою новую заявку | Новая или отменённая запись | Новая или отменённая запись |
| Учётные записи | Свой пароль | Свой пароль | Создание, список, изменение имени и роли, включение/отключение |

Удалить используемый справочник нельзя. Оплаченный билет нельзя исправлять или физически удалять: сотрудник оформляет отмену, а при необходимости создаёт новую заявку. Отменённые записи не восстанавливаются. Администратор также соблюдает эти бизнес-правила. Учётные записи отключаются, а не удаляются; администраторов нельзя отключить или понизить в роли.

## 1. Подготовка администратором

1. Запустить PostgreSQL и backend по README, затем JavaFX через `run.sh` / `run.ps1`.
2. Войти с первоначальными реквизитами из `.env`, заменить временный пароль.
3. На вкладке «Клиенты и мероприятия» добавить будущее мероприятие: название, место, дата, время и цена.
4. Покупатели могут зарегистрироваться самостоятельно. При необходимости администратор также может выдать покупателю учётную запись с временным паролем; профиль создаётся автоматически.
5. Там же создать менеджера. Передать каждому его логин и временный пароль.

При самостоятельной регистрации роль всегда «Пользователь». Менеджеров и администраторов создаёт только администратор. Для старых VIEWER миграция создаёт собственные профили, не присваивая существующие билеты по имени.

## 2. Покупатель бронирует билет

1. На экране входа нажать «Нет аккаунта? Зарегистрироваться». Указать имя, уникальный логин (3–40 символов: латиница, цифры, точка, дефис, подчёркивание), пароль (12–128 символов) и подтверждение. После регистрации сразу откроется личный кабинет. При следующих запусках использовать «Войти». Если учётную запись выдал администратор, при первом входе заменить временный пароль.
2. В «Афише» посмотреть будущие мероприятия.
3. В «Моих билетах» нажать «Забронировать билет», выбрать мероприятие. Клиент уже выбран и заблокирован; цену вводить не нужно.
4. Сохранить: появится заявка «Новое». Она видна менеджеру. Обновление между сеансами выполняется кнопкой «Обновить».
5. До подтверждения выбрать заявку → «Редактировать». Можно заменить мероприятие или выбрать «Отменено». Цена нового мероприятия подставится автоматически; прежний тариф сохраняется при возврате к исходному событию.
6. Если заявка создана ошибочно, выбрать её → «Удалить» → подтвердить. Это доступно только для статуса «Новое».
7. После подтверждения менеджером реквизиты заблокированы. До оплаты и начала события можно отменить заявку через редактирование статуса.
8. После оплаты билет доступен для просмотра и экспорта. Для отмены оплаченного билета обратиться к сотруднику.

## 3. Менеджер обрабатывает заявку

1. Войти и открыть «Заявки и билеты». Обновить данные, выбрать фильтр «Новое».
2. Открыть «Подробнее», проверить клиента, мероприятие, дату и цену.
3. При необходимости исправить новую заявку через «Редактировать».
4. Выбрать статус «Подтверждено» и сохранить. Покупатель увидит результат после обновления.
5. После получения оплаты выбрать «Оплачено». Без предварительного подтверждения такая операция запрещена.
6. Если подтверждённой заявке нужны исправления, вернуть её в «Новое», затем изменить данные и подтвердить заново.
7. При отказе выбрать «Отменено». Если билет был оплачен, возврат денег оформляется отдельно; приложение не переводит деньги.
8. Для очистки ошибочной записи можно удалить новую или отменённую запись с подтверждением. Оплаченные и подтверждённые напрямую не удаляются.

Менеджер может создать заявку за существующего клиента. Изменять справочники и учётные записи он не может.

## 4. Администратор контролирует систему

1. Просматривать все заявки и общую статистику, фильтровать по клиенту, мероприятию, статусу и периоду, экспортировать текущий список.
2. Исправлять новые заявки, подтверждать и отменять их как менеджер.
3. В справочниках выбрать клиента/мероприятие → «Изменить». При изменении тарифа цены уже созданных билетов сохраняются.
4. Удалять только неиспользуемые справочники; при наличии ссылок система объяснит запрет.
5. В «Пользователях» менять имя и роль выбранной учётной записи. Логин сохраняется, прежние сеансы отзываются, профиль покупателя сохраняется при смене роли.
6. Отключать/включать доступ менеджеров и пользователей с подтверждением.

## Жизненный цикл

`Новое → Подтверждено → Оплачено → Отменено`.

Из «Новое» и «Подтверждено» также возможна отмена; менеджер может вернуть «Подтверждено» в «Новое». Пользователь не может подтвердить заявку или сам отметить оплату. Факт оплаты регистрирует сотрудник, банковской интеграции нет. Цена, статус и ссылки сохраняются атомарно. Если запись уже изменена другим пользователем, нужно обновить список и открыть форму заново.
