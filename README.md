# TicketPoint

TicketPoint — система управления билетными бронированиями. Она объединяет веб-приложение и настольный клиент: сотрудники ведут мероприятия, клиентов и заявки, а покупатели следят за своими билетами.

Веб-клиент и JavaFX-приложение работают с одной базой PostgreSQL. Веб-клиент обращается к ней через REST API, а настольное приложение подключается напрямую через JDBC.

## Возможности

- Бронирования с номером билета, клиентом, мероприятием, ценой и статусом.
- Поиск, фильтры, сортировка и постраничный просмотр.
- Жизненный цикл заявки: новая → подтверждённая → оплаченная; отмена и архив.
- Управление клиентами и мероприятиями.
- Роли и доступ: покупатель, наблюдатель, менеджер, администратор.
- Аналитика, заметки, метки, массовые операции и журнал аудита в веб-клиенте.
- Предварительная проверка импорта CSV и экспорт CSV из веб-клиента; экспорт Excel из JavaFX.
- Регистрация покупателей и управление пользователями администраторами.

## Технологии

| Часть | Стек |
| --- | --- |
| Backend и API | Java 21, Spring Boot, Spring Data JPA, Spring Security, Flyway |
| Веб-клиент | HTML, CSS, JavaScript |
| Настольный клиент | JavaFX, FXML, JDBC |
| Хранение данных | PostgreSQL 17 |
| Сборка и запуск | Maven Wrapper, Docker Compose |

## Быстрый старт

### Требования

- Java 21 или новее
- Docker с Docker Compose
- Графическое окружение для запуска JavaFX-клиента

### 1. Настройте окружение

Скопируйте пример конфигурации и задайте собственные пароли и секрет:

```bash
cp .env.example .env
```

В `.env` заполните `POSTGRES_PASSWORD`, `BOOTSTRAP_ADMIN_PASSWORD` и `JWT_SECRET_BASE64`. Сгенерировать секрет JWT можно командой:

```bash
openssl rand -base64 32
```

Не публикуйте `.env` и не используйте демонстрационные пароли в рабочем окружении.

### 2. Запустите базу данных и backend

Из корня проекта:

```bash
docker compose up -d --build --wait
```

После запуска откройте [http://localhost:8080](http://localhost:8080). Проверить состояние backend можно по адресу [http://localhost:8080/actuator/health](http://localhost:8080/actuator/health). При первом запуске Flyway создаст схему и демонстрационные записи. Начальный администратор создаётся из параметров `BOOTSTRAP_ADMIN_*`, если в базе ещё нет пользователей.

### 3. Запустите настольный клиент (по желанию)

Оставьте Docker-сервисы запущенными и выполните в отдельном терминале:

```bash
./run.sh
```

В Windows PowerShell:

```powershell
powershell -ExecutionPolicy Bypass -File .\run.ps1
```

Используйте ту же учётную запись, что и в веб-клиенте. JavaFX-клиент подключается к PostgreSQL напрямую, поэтому при необходимости настройки подключения задаются через `.env`.

## Сборка и запуск

Собрать все модули:

```bash
./mvnw clean package
```

Запустить тесты:

```bash
./mvnw test
```

Для Windows используйте `.\mvnw.cmd`.

Остановить контейнеры, сохранив данные:

```bash
docker compose stop
```

PostgreSQL хранит данные в Docker volume `ticketpoint_data`. Команда `docker compose down -v` удаляет этот volume вместе с данными.

## Структура проекта

```text
core/             Общие модели, бизнес-логика, JDBC-репозитории и консольный клиент
javafx-client/    Настольный интерфейс на JavaFX
backend/          Spring Boot REST API и встроенный веб-клиент
db/               SQL-схема, начальные данные и миграции
```

## Архитектура

```text
Веб-браузер ── REST API ── Spring Boot / JPA ──┐
                                               ├── PostgreSQL
JavaFX ───────────── JDBC ──────────────────────┘
```

Backend использует JWT-аутентификацию и разграничивает операции по ролям. Изменения доступны веб-клиенту и JavaFX после обновления данных. Схему базы обновляет Flyway.

## Настройки

Основные параметры задаются в `.env`:

| Переменная | Назначение |
| --- | --- |
| `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD` | Реквизиты PostgreSQL |
| `POSTGRES_PORT` | Порт PostgreSQL на компьютере, по умолчанию `5433` |
| `BACKEND_PORT` | Порт веб-приложения и API, по умолчанию `8080` |
| `BOOTSTRAP_ADMIN_LOGIN`, `BOOTSTRAP_ADMIN_NAME`, `BOOTSTRAP_ADMIN_PASSWORD` | Начальная учётная запись администратора |
| `JWT_SECRET_BASE64` | Секрет подписи JWT, не менее 32 случайных байт в Base64 |
| `APP_ZONE` | Часовой пояс, по умолчанию `Europe/Moscow` |

Шаблон со всеми доступными переменными находится в [`.env.example`](.env.example). Не меняйте параметры подключения независимо друг от друга: при изменении порта или имени базы синхронизируйте `POSTGRES_PORT`/`DB_URL` или `POSTGRES_DB`/`DB_URL`.
