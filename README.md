# TicketPoint

Настольное приложение для управления билетными бронированиями. Позволяет вести список клиентов и мероприятий, создавать билеты, менять их статус и выгружать список бронирований в Excel.

Написано на Java 21 и JavaFX. Данные хранятся в PostgreSQL, приложение подключается к базе через JDBC.

Учебный проект по программированию корпоративных систем. JavaFX-версия продолжает консольное приложение из первой контрольной работы.

## Возможности

- Создание бронирований с выбором клиента и мероприятия из списка.
- Изменение статуса билета и удаление с подтверждением.
- Просмотр и добавление клиентов и мероприятий.
- Поиск по номеру билета, имени и коду клиента, названию и месту мероприятия.
- Фильтры по статусу, клиенту, мероприятию и периоду дат.
- Сортировка по столбцам таблицы.
- Статистика: всего бронирований, новые, оплаченные, отменённые, билеты от 5 000 ₽ и доля оплаченных.
- Экспорт видимого списка в `.xlsx` с сохранением фильтров и порядка строк.
- Проверка обязательных полей, длины текста, даты, времени и цены.

Номер билета создаётся автоматически. Цена фиксируется при бронировании и не меняется при изменении цены мероприятия. Новый билет получает статус «Новое». Оплаченный билет нельзя вернуть в этот статус, а отменённый нельзя редактировать. Создать бронирование можно только на мероприятие, которое ещё не началось.

## Требования

- JDK 21 или новее.
- Docker Desktop либо Docker Engine с поддержкой `docker compose`.
- Графическое окружение для запуска JavaFX.

Maven 3.9 загружается через Wrapper, отдельная установка не требуется. При первом запуске нужен доступ к интернету для загрузки Maven, зависимостей и образа PostgreSQL.

## Быстрый запуск

Все команды выполняются из корня проекта. Сначала запустите Docker.

### macOS и Linux

1. Создайте файл настроек:

   ```bash
   cp .env.example .env
   ```

2. Откройте `.env` и заполните `POSTGRES_PASSWORD`. Значения `DB_USER` и `DB_PASSWORD` уже ссылаются на настройки PostgreSQL. Если `.env` существует, используйте его.

3. Запустите базу и приложение:

   ```bash
   docker compose up -d --wait postgres
   ./run.sh
   ```

### Windows

1. В PowerShell создайте файл настроек:

   ```powershell
   Copy-Item .env.example .env
   ```

2. Откройте `.env` и заполните `POSTGRES_PASSWORD`. Существующий файл настроек повторно копировать не нужно.

3. Запустите базу и приложение:

   ```powershell
   docker compose up -d --wait postgres
   powershell -ExecutionPolicy Bypass -File .\run.ps1
   ```

PostgreSQL работает в Docker, JavaFX запускается на компьютере. Приложение автоматически читает `.env` из текущего рабочего каталога. Переменные окружения имеют приоритет над значениями файла. Скрипты запуска выполняют Maven goal `javafx:run` из корня проекта.

При первом запуске на пустой базе автоматически выполняются [schema.sql](db/schema.sql) и [seed.sql](db/seed.sql): создаются таблицы, 5 клиентов, 3 мероприятия и 10 бронирований. При последующих запусках данные сохраняются.

### Запуск из IntelliJ IDEA

Откройте проект как Maven-проект. Укажите JDK 21 или новее в Project SDK и Maven Runner JRE. Создайте и заполните `.env`, запустите PostgreSQL. В конфигурации запуска укажите корень проекта в поле Working directory.

Запустите класс `ru.ticketpoint.fx.FxLauncher` или Maven goal `javafx:run`. Настройки из `.env` загрузятся автоматически. При необходимости их можно переопределить переменными окружения конфигурации запуска.

## Настройки

Пример настроек находится в [.env.example](.env.example). Локальный `.env` исключён из Git.

| Переменная                     | По умолчанию                                   | Назначение                              |
| ------------------------------ | ---------------------------------------------- | --------------------------------------- |
| `POSTGRES_DB`                  | `ticketpoint`                                  | Имя базы в Docker                       |
| `POSTGRES_USER`                | `ticketpoint`                                  | Пользователь базы в Docker              |
| `POSTGRES_PASSWORD`            | Нужно заполнить                                | Пароль базы в Docker                    |
| `POSTGRES_PORT`                | `5432`                                         | Порт PostgreSQL на компьютере           |
| `DB_URL`                       | `jdbc:postgresql://localhost:5432/ticketpoint` | Адрес JDBC-подключения                  |
| `DB_USER`                      | `${POSTGRES_USER}`                             | Пользователь для подключения приложения |
| `DB_PASSWORD`                  | `${POSTGRES_PASSWORD}`                         | Пароль для подключения приложения       |
| `APP_ZONE`                     | `Europe/Moscow`                                | Часовой пояс дат                        |
| `DB_CONNECT_TIMEOUT_SECONDS`   | `5`                                            | Время ожидания подключения              |
| `DB_STATEMENT_TIMEOUT_SECONDS` | `15`                                           | Время выполнения SQL-запроса            |
| `DB_SOCKET_TIMEOUT_SECONDS`    | `30`                                           | Время ожидания ответа по сети           |

Если порт `5432` занят, добавьте в `.env` другой `POSTGRES_PORT` и измените порт в `DB_URL`. При изменении имени базы обновите также `DB_URL`.

Для подключения к существующей базе укажите её адрес, пользователя и пароль в `DB_URL`, `DB_USER` и `DB_PASSWORD`. Структура базы должна соответствовать `db/schema.sql`. Создавать контейнер из этого проекта в таком случае не требуется.

## Работа с приложением

На вкладке «Клиенты и мероприятия» заполните справочники. На вкладке «Бронирования» создайте билет, выбрав клиента и мероприятие. Данные билета отображаются в таблице. Для редактирования статуса или удаления выберите строку.

Поиск и фильтры работают совместно. Если новая запись не видна, проверьте активные фильтры. Для сортировки нажмите заголовок столбца; удерживайте Shift, чтобы выбрать несколько столбцов. Кнопка «Обновить» загружает актуальные данные из базы.

«Экспорт Excel» сохраняет текущий список в выбранный файл. На вкладке «Статистика» показатели рассчитываются по всей базе, независимо от фильтров.

## Сборка и тесты

```bash
./mvnw test
./mvnw clean package
```

В Windows используйте `.\mvnw.cmd` вместо `./mvnw`. Обычный запуск тестов пропускает проверки PostgreSQL и JavaFX.

Для полной проверки на macOS или Linux запустите PostgreSQL и выполните в Bash:

```bash
set -a
source .env
set +a
export TEST_DB_URL="$DB_URL" TEST_DB_USER="$DB_USER" TEST_DB_PASSWORD="$DB_PASSWORD"
export RUN_FX_TESTS=true
./mvnw clean verify
```

Проверки базы создают отдельные временные схемы и удаляют их после выполнения. Тестовому пользователю нужны права на создание схем. Проверки JavaFX открывают тестовые окна и требуют графического окружения.

Собранное приложение находится в `target/ticketpoint-1.0-SNAPSHOT.jar`. Запустите его из корня проекта, где находится `.env`:

```bash
java -jar target/ticketpoint-1.0-SNAPSHOT.jar
```

JAR содержит JavaFX для платформы, на которой выполнена сборка. Для другой ОС соберите проект на ней.

Консольный режим и служебные команды также читают настройки из `.env`:

```bash
java -jar target/ticketpoint-1.0-SNAPSHOT.jar --console
java -jar target/ticketpoint-1.0-SNAPSHOT.jar --check
java -jar target/ticketpoint-1.0-SNAPSHOT.jar --export exports/bookings.xlsx
```

## Если не запускается

- **База недоступна:** проверьте, что Docker запущен, затем выполните `docker compose ps`. У PostgreSQL должен быть статус `healthy`.
- **Неверный пароль:** проверьте `.env`. Изменение `POSTGRES_PASSWORD` не меняет пароль пользователя в уже созданной базе.
- **Не найдены таблицы:** проверьте `DB_URL` и структуру базы. Init-скрипты Docker выполняются только при первом запуске с пустым хранилищем.
- **Неверная версия Java:** проверьте `java -version`, `JAVA_HOME` и JDK в настройках IDE.

Технические подробности ошибок записываются в `logs/ticketpoint-*.log`.

Для остановки базы:

```bash
docker compose stop postgres
```

Данные сохраняются в Docker volume. Команда `docker compose down -v` удаляет хранилище базы.
